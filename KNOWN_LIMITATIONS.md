# Known limitations

## ATTRICI compatibility baseline

The operational COMPASS calculations represented by this repository were developed with a local ATTRICI-derived runtime based on the `v2.0.1`-`v2.0.3` development line. The exact local source used by the workflow is included under `vendor/attrici` as a frozen compatibility snapshot.

The snapshot is not a new ATTRICI release and is not offered as a general-purpose fork. Within this public repository its role is limited to applying compatible pre-fitted traces to newly available factual data through the COMPASS counterfactual wrapper.

The ATTRICI maintainers currently warn that releases from v2.0 onward contain an issue that mainly affects precipitation (`pr`) and surface downwelling shortwave radiation (`rsds`), and recommend v1.1.0 for production use until a fix is available. The COMPASS historical products had already been generated with the v2-based workflow before this warning was assessed.

This release therefore preserves the historical implementation for reproducibility. It does **not** claim to correct the upstream issue. Results made with this implementation should be labelled accordingly and must not be mixed silently with products generated by a future corrected implementation.

Before migrating, the project should define a controlled validation exercise for `pr` and `rsds`, quantify the impact on derived hazards and crop results, and decide whether historical products require recalculation. That migration is outside this release.

## Supported ATTRICI execution profile

The documented and supported COMPASS profile is PyMC5 with four Fourier modes, `--trace-file`, `--full-extrapolation`, the matching calibration-era GMT predictor, and the six core variables listed in `attrici/README.md`.

The following uses are outside the validated scope of this release:

- fitting or training new ATTRICI traces;
- the SciPy and PyMC3 solver paths;
- rolling-window fitting through `window_size`;
- replacing or extending the GMT predictor without checking its compatibility with the traces;
- treating `vendor/attrici` or `patches/attrici-compass.patch` as a new upstream ATTRICI distribution.

Some local safeguards can change individual counterfactual values. In particular, the snapshot may replace invalid or project-defined extreme quantile-mapping results with the corresponding factual value. This behaviour supported operational continuity, but it is not presented as a methodological correction. Logs and validation reports should record whether replacements occurred.

Trace coordinates may be matched to factual coordinates by nearest neighbour within a small tolerance. The supplied preflight checks should be used to confirm complete grid coverage; the tolerance is not permission to combine scientifically different grids.

## Data availability

Input data, fitted ATTRICI traces, the GMT predictor, LISVAP basemaps/configuration, historical crop tables, and generated products are not distributed in Git. The code cannot complete an end-to-end scientific run until users provide compatible inputs described in the module guides.

## Scientific and operational validation

The repository includes static safety checks and input preflight checks. It does not include a reference dataset small enough to validate the complete numerical workflow in continuous integration. Passing CI therefore confirms repository structure and syntax, not scientific equivalence or numerical correctness. Reproduction claims should identify the input checksums, software environments, configuration, replacement warnings, and validation results used for a run.

## Platform scope

The daily-data code was developed on Linux and WSL, while the documented operational ATTRICI execution was verified in the project's macOS environment. Cross-platform numerical equivalence and complete portability have not been established. Users should perform a selected-cell comparison before scaling the workflow on a new platform.
